# Deploying the public demo

Everything here runs on free plans. Limits were checked on 2026-11-15; free
plans change, so check the linked pages again before relying on a number.

| Part | Host | Free limit that matters | Source |
|---|---|---|---|
| API (Docker) | Render web service | Stops after 15 min without traffic, up to a minute to start again; 750 instance hours per workspace per month | [render.com/docs/free](https://render.com/docs/free) |
| PostgreSQL | Neon | 1 GB storage and 100 CU-hours per project per month | [neon.com/faqs/free-plan-limits-and-quotas](https://neon.com/faqs/free-plan-limits-and-quotas) |
| Redis | Upstash | 500,000 commands per month, 256 MB, one free database | [upstash.com/pricing/redis](https://upstash.com/pricing/redis) |
| Dashboard | Cloudflare Workers (static assets) | Static files only | |
| LLM | Gemini, then Groq | Per-project limits shown in each console | |

Not confirmed from an official page: Render's 512 MB memory figure and whether
any of these hosts asks for a card at sign-up. If one does, stop: the project
rule is no card (see "Alternatives" below).

## Order

1. **Neon.** Create a project in an EU region. Copy the *direct* connection
   string, not the pooled one (the pooler breaks asyncpg's prepared statements).
   The `postgresql://…?sslmode=require&channel_binding=require` form works as
   is; the app translates it for its driver.
   With the Neon CLI (`neon deploy` writes `.env.local`), this is the value of
   `DATABASE_URL_UNPOOLED`, not `DATABASE_URL`. Checked on 2026-11-15: migrations,
   guest sign-in, a playground call and the audit check all pass against Neon.
2. **Upstash.** Create a Redis database in an EU region. Copy the `rediss://` URL.
3. **LLM keys.** Create a Gemini key (Google AI Studio) and a Groq key. Both are
   optional: with neither, set `LLM_MODE=replay` and the demo answers from a
   recording.
4. **Render.** New → Blueprint → pick this repository; `render.yaml` describes
   the service. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Neon connection string |
   | `REDIS_URL` | Upstash URL |
   | `CORS_ORIGINS` | `["https://<your-project>.pages.dev"]` (JSON list) |
   | `GEMINI_API_KEY`, `GROQ_API_KEY` | the keys, or leave empty |
   | `METRICS_TOKEN` | a random string, or leave empty to switch `/metrics` off |

   `JWT_SECRET` is generated by Render. Migrations run each time the container
   starts (`alembic upgrade head` is a no-op when nothing changed).
5. **Cloudflare Workers.** Workers & Pages → Create → import the repository.
   Path `/web`, build command `npm run build`, deploy command `npx wrangler deploy`.
   `web/wrangler.jsonc` serves `dist` and names the API address (`API_ORIGIN`);
   `web/worker.js` forwards `/api/*` to it, so the browser only ever talks to the
   dashboard's own address (ADR 0005).
   Then create one random value and set it in both places as `PROXY_SECRET`:
   Cloudflare (Worker → Settings → Variables and Secrets → type *Secret*) and
   Render (Environment). It lets the API trust the visitor address the Worker
   reports. Without it the demo works, but visitors may share one sign-in limit.
6. **Keep-warm.** Nothing to set up. The Worker has a Cron Trigger
   (`triggers.crons` in `web/wrangler.jsonc`) that requests the API's `/healthz`
   every 10 minutes from 05:00 to 22:59 UTC. Check it under Worker → Settings →
   Trigger Events, and its runs under Worker → Logs.

## Check after the first deploy

- `curl https://<api>/readyz` reports `postgres` and `redis` as `ok`.
- Open the dashboard in a private window, click "Try the live demo", send the
  example message. The answer should name a real provider, not "recording".
- **Client address.** Checked on 2026-11-16: with `TRUSTED_PROXY_HOPS=1` alone, 12
  guest sign-ins with a different forged `X-Forwarded-For` each all succeeded, so
  that header does not identify visitors on Render. The blueprint therefore sets
  `CLIENT_IP_HEADER=CF-Connecting-IP`. Repeat the test after a deploy: more than 10
  sign-ins from one machine within an hour must end in "Too many requests", whatever
  headers are sent. Independent of this, all visitors together are capped at
  `GUEST_LOGINS_PER_HOUR_TOTAL` (60) new sandboxes per hour.
- **Model names.** Defaults are `gemini-3.5-flash` (confirmed working on 2026-11-16)
  and `openai/gpt-oss-120b` (not yet confirmed).
  Providers retire models on short notice (Groq retired `llama-3.3-70b-versatile`
  in August 2026). If the dashboard only ever answers from the recording, look
  for `provider_failed` in the logs and set `GEMINI_MODEL` / `GROQ_MODEL`.

## What keeps the demo inside the free limits

- **Redis commands.** One gateway call costs about 8 commands (rate limit, cache
  read and write, guest budget, stream add, read, acknowledge). 500,000 per
  month is therefore roughly 2,000 calls a day. An idle server issues one
  command every 5 minutes.
- **LLM quota.** All guest sandboxes share `GUEST_DAILY_LLM_CALLS` (default 200)
  live calls per UTC day. After that guests get the recording until midnight UTC;
  redaction, audit log and dashboard keep working.
- **Guest sign-ins.** 10 per hour per visitor address.
- **Memory.** About 185 MB at rest, about 320 MB for a moment while the language
  model loads at start.
- **Keep-warm.** About 560 container hours a month, inside Render's 750 free
  hours. Pinging around the clock would use about 744, which leaves no room for
  a second service. A GitHub Actions schedule was tried first and dropped:
  GitHub ran it a few times a day instead of every 10 minutes.

## Alternatives

- Koyeb instead of Render: same image, same variables, start command `sh start.sh`.
- Any Kubernetes cluster: `deploy/helm/docuvault` (see the README).
